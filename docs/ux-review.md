# 用户视角体验评审 · 特码智能选号助手

> 方式：不读 README，直接以新用户身份用 JSDOM 把页面跑起来，模拟"打开 → 看 → 点档位 → 复制 → 锁定 → 同步 → 导出"的完整流程，记录每一步的原文与困惑点。
> 与 `docs/probability-review.md`（概率/算法评审）互补：这份只关心**用户能不能看懂、能不能完成目标、有没有被误导**。

---

## 一、一句话总评

**"几分钟能用清"的部分做得不错（球色、档位、复制、锁定、自动核对），但"能不能信任/能不能看懂"的部分问题明显。** 最大的用户价值缺口是：页面从头到尾不给"投入多少、覆盖多少、期望亏多少"，反而用一组永远点亮的中性噪声（连错 7 期、相对占优、双策共振）占据了"下期智能主推"最显眼的位置。

下面按用户真实会撞到的顺序排，全部是代码/实测定位过的，不是印象。

---

## 二、P0：直接影响"用"的（4 个）

### 1. 「一键同步」点了没反应 —— 最要紧的信任问题

实测（`src/note-sync.js`）：

```js
if (!rows.length) { status.textContent = '同步完成，没有新期次。'; return; }
```

`return` 发生在 `finally` **之前**，`finally { button.disabled = false; }` 虽然会执行，但更关键的是：

- **失败时"没有新期次"和"网络挂了"共用同一个成功语气的文案**，状态条不会变红；
- 而 `planSync()` 一旦抛错（"期号缺口：应为 X"、"与本地记录冲突"），文案是 `未写入：期号缺口：应为 2026-328…` —— **术语 + 红色缺失**，用户只会理解成"这软件坏了"；
- 实测在无网环境下，点击后状态条**长时间停留在"点击「一键同步」获取最新开奖结果。""**（初始文案一字不变），用户无法判断是"没反应"还是"正在转"。

建议（按性价比排序）：
1. 状态文案改成三态：`正在同步… / ✅ 已更新到 2026-327 / ⚠️ 无新数据（上游最新仍是 2026-326）`，失败用 `.warn` 红色；
2. 给按钮加同步中的 loading 态（现在只有 `disabled`，视觉上几乎无差别）；
3. 把 `期号缺口 / 记录冲突` 翻成人话：`数据源第 2026-328 期与本地缺失的第 2026-327 期不连续，已跳过不写入`。

### 2. 失败/空态不可见 —— "数据不足"这一类分支用户根本看不到解释

- `renderThermometer()` 在 `!rows.length` 时只输出 `数据不足，暂无温度计`，`#thermoBaseline` 文案**仍是 7 码的 14.3%**；
- `renderSignal()` 在无数据时 `数据不足，暂不输出信号。`，但徽章仍是 `当前连错 -- 期`；
- 首次打开、清空本机数据、或底库异常时，页面会出现**一堆 `--` 和 `(缺失)`**，但没有任何"下一步该做什么"的引导（比如"点击一键同步"或"去数据管理手动补录"）。

用户的真实感受：**看到 `--` 不知道是加载中还是坏了**。建议所有空态统一成"状态 + 原因 + 一个可点的按钮"。

### 3. 「下期智能主推」被噪音占位 —— 首屏最贵的位置放了最没用的信息

实测首屏（1400×900 桌面，`mainPickSection` 在 `thermometerSection` 之后）：

```
系统参考信号：主推已连续 8 期未中，建议谨慎参考；近30期「#3 周期」相对占优（8/30，27%）。
[当前连错 8 期] [近20期5码中 3 期]
```

这段话的问题不是"数据不对"，而是**它把一个纯随机事件说成了建议**：

- 5 码档下，"连错 8 期"是**必然会发生**的（单期不中 89.8%，连错 8 期概率 42%，30 期窗口内几乎 100%）；
- 实测切换档位后，连错数从 8 变 7 变 5，同一期开出三个不同答案（`5码→8`、`10码→7`、`并集→5`），用户会以为"系统在重新判断"，其实只是分母变了；
- `#3 周期 相对占优（8/30，27%）`：27% 与 7 码基线的 14.3% 在 30 期样本里**没有统计差异**（见概率报告），但"相对占优"四个字会被读成"这组更准"。

建议：把这一栏换成**与决策真正相关**的三件事：
```
本期 10 码：10 注 · 覆盖 10/49 (20.4%) · 每期期望净亏 ¥2.04
近 30 期该档命中 6 期（随机基线 14.3%±12.5pp，无显著差异）
```
信号条要么删除，要么改成"本期与随机无显著差异（z=0.11）"——**保留负反馈，去掉伪建议**。

### 4. 「一键复制」在手机上够不到 —— 用户最核心的动作藏在滚动区里

`copyMainBtn` 在主推卡片里，而主推卡片在当前 6 卡布局中是**第 3 屏**（顶部栏 → 温度计 → 主推）。手机端 `.page` 宽 375px 时，温度计 3 行 + 说明 + 主推标题 + 信号条，复制按钮已经在第一屏之外。

`assets/styles.css` 里写了 `.mobile-copy-bar { position: fixed; bottom: 0 }` 的**吸底复制条**，但 `index.html` 里 `mobile-copy-bar` 出现 **0 次**（样式是死的），`.app-main` 也是 0 次 —— 这份 CSS 是另一个版本页面的遗留，没有接到当前单页上。

建议：要么把主推卡片提到温度计之前（移动端 `order`），要么真的实现吸底复制条；顺带把 `.app-main / .mobile-copy-bar / .brand-title` 这批未使用的样式清掉（`assets/styles.css` 共 712 行，实测只有内联 `<style>` 里的规则生效）。

## 三、P1：影响"看得懂"的（5 个）

### 5. 术语墙：6 套黑话，用户第一次看全都不认识

实测页面出现但**没有任何解释**的术语：

| 术语 | 出现位置 | 用户会理解成 |
| --- | --- | --- |
| `双策共振` | 号码标签（`03 双策共振`） | ？？？ |
| `并集全取 18码` | 档位按钮 | 并集是什么？ |
| `本档构成 含热态 7 含遗漏 0 含周期 3 多策共识 3` | 主推下方 | 6 个数字，没有单位 |
| `减半/观望/严禁倍投追号` | 信号条文案 | 谁在倍投？ |
| `底库 / 有效 1786 期` | 顶部 | 底库是数据库？ |
| `同步于 12:25` | 顶部 | 这是同步开奖还是同步时间？ |

而且 `双策共振` 只在代码里定义（`count === 2`），页面上**没有图例**；`本档构成` 的"含热态 7"实际是"这 7 个号里属于#1 热态的有 7 个"，但写成 `含热态 7` 会被读成"热态有 7 个号"（碰巧数字一样，一旦是 3 就很费解）。

建议：给 `波色图例` 旁边加一个 `?` 按钮，点开一个 12 行的小图例表（`热态/遗漏/周期/双策共振/并集/本档构成/连错`），一次把 6 个词说清；`本档构成` 改成 `热态 7 · 遗漏 0 · 周期 3 · 共识 3`，去掉"含"。

### 6. 「锁定了却看不见」 —— 锁定后的号码在"本地锁定记录"折叠区里

实测点「锁定本期」后：
- 按钮变「解除锁定」，锁定区显示 `已锁定 10 码 2026/11/23 12:25:11 03 05 15 …`，**这部分是对的**；
- 但锁定记录列表 `lockFold` **默认折叠**，`lockHistoryCount 0 条` 在首屏看不到；
- 更关键：锁定的是**当前档位**，切到 7 码档后锁定区不更新（按设计），但**页面没有任何提示"你锁定的是 10 码档"**。实测 `已锁定 10 码` 是有的，但用户切档后会以为"锁定也跟着变了"。

建议：切档时在锁定区加一行 `· 当前显示 7 码；已锁定的是 10 码`。

### 7. 「一键复制」到底复制了什么，用户不确认

实测复制内容是 `03，05，15，19，21，23，26，38，46，47`（中文逗号），卡片下方有一行小字 `复制格式（中文逗号分隔）`，但没有 `已复制 ✓` 的持久反馈——`handleCopyButton` 只把按钮文字改 1.2 秒再改回来（`setTimeout(...1200)`），在手机上 1.2 秒的 toast 很容易错过，用户会连点三次。

建议：复制后按钮变 `✅ 已复制 10 码`，并保留到切档；同时把复制内容在卡片里做成可选择文本（`user-select: text`），让用户能手动复制。

### 8. 30 期命中简表：一屏 20 个 `-`

实测默认 10 码档：30 行里 **20 行是 `-`**（未中），只有 10 行有命中数字。`-` 在不同列（当前档位 / #1 / #2 / #3）出现四次，视觉上全是"没中"的负反馈，却**没有任何一行总结**（如 `30 期中 10 期 · 最长连错 5 期 · 合计 100 注中 10 注`）。

pill `最近 30 期 · 当前10码中 10 期` 是有的，但它是一个灰色小 pill，权重远低于表格本身。

建议：表格上方加一行总结（复用 pill 的计算，放大成一行），并把未中的 `-` 改成浅灰点 `·`，减少视觉噪音；命中行已有 `row-hit` 高亮，可以再加"命中号码"在行内直接显示（现在要点"展开 ▾"）。

### 9. 数据管理里的"导出备份"是个陷阱

实测导出文件内容：

```json
{ "app": "特码智能选号助手", "schemaVersion": 3,
  "draws": [...], "labels": [...], "locked": {...}, "locks": [...] }
```

但 **`draws` 只包含 `manualRecords`（用户手动补录的记录），不包含内置底库 1786 期**。文案叫"导出备份"，用户会以为整个工具+历史都在里面；换台手机导入后，会以为"底库丢了"（其实内置底库随 HTML 一起走，但用户不知道）。

建议：文案改成 `导出本机新增记录与锁定（不含内置底库）`，或在导出文件里加 `builtInDatabase: "2026-326 / 1786期"` 字段并在导入时提示"内置底库已随应用更新到 X 期"。

## 四、P2：小但真实的毛刺（选摘）

10. **顶部时间戳永远是"现在"，不是"数据同步时间"**：`updateDataStatus()` 用 `new Date()` 生成 `同步于 12:25`，每次打开页面都会刷新。用户会以为"数据是 12:25 同步的"，实际是"你现在打开的时间"。应改成 `数据截至 2026-326（2026-11-22）· 本地校验于 12:25`。
11. **窄屏档位按钮会撑破**：`.tier-tabs` 是 `grid-template-columns: repeat(5, minmax(0,1fr))`，320px 宽下每个按钮 60px，`并集全取 18码` 的中文标签会换行到 2–3 行，高度不齐（CSS 里没有 `text-overflow` 或收缩策略）。建议 375px 以下把档位改成横向滚动条（`overflow-x:auto; grid-auto-flow:column`）。
12. **没有"本期截售/开奖时间"**：用户最关心"我什么时候之前要买"，页面只有"上期开奖日期"。可以在顶部加 `今晚 21:15 开奖 · 距截售 X 小时`（数据源有每日开奖规律）。
13. **"近 100 期热度分布"用的其实是"近 100 期"，但热度格没有说明"这是统计窗口"**：`heatLiveBadge` 显示"截至 2026-326"，标题写"近 100 期"，但格子里是 0–N 次。用户不知道 N 的分母。建议格子里含义写进 legend（已有 `≥5次 热` 等，但没写"近 100 期特码"）。
14. **色盲不友好**：波色只靠红/蓝/绿区分，`data-wave` 有但视觉上没有形状差异（圆点颜色 + 背景色）。建议在球上叠加极小图形（如红波加 `●`、蓝波加 `▲`）或给盲用户提供 `title`。
15. **`并集全取 18码` 的码数不是固定的**：实测全历史 14–21 码（平均 18.2），但按钮文案 `并集全取 18码` 用的是当期实际数量——用户如果按"18 码 = 18 注 = ¥180"做预算，会有 ±30% 偏差。这一条与 `docs/probability-review.md` 的 P1-6 是同一个根因。
16. **模态框关闭后焦点丢失**：`Escape` 和点击背景都能关（实现没问题），但关闭后焦点没有回到触发按钮（`openHistoryModal`），键盘用户可以连续 Tab 但不知道自己在哪。加 `trigger.focus()` 即可。

## 五、已经做得好的（不要动）

- 号码球按红/蓝/绿渲染 + 特码高亮（`draw-ball-item.is-sp`），视觉辨识度高；
- 档位切换即时刷新主推、温度计、信号、简表，**联动完整**（实测 5→18 码切换全部同步）；
- 锁定 → 同步后自动核对命中，`lockHistory` 归档 + 导出一起保存，流程闭环；
- 空/坏数据有 `audit.js` 隔离（2022-132 那期坏行被排除，没有静默补全）；
- 历史弹窗的年度命中率总表 + 期号搜索 + 仅看命中，功能密度高且都在一个弹窗里，是**最适合"快速回看"的形态**；
- 移动端把表格转成卡片（`@media (max-width:720px)` 的 `thead{display:none}` + 块级 `tr`），这个决策是对的。

## 六、如果只改 3 件事

1. **把「一键同步」做成三态 + loading**（P0-1）—— 这是用户唯一会主动点的按钮，现在它"没反应"。
2. **主推卡片加一行成本/覆盖/期望**（P0-3）—— `10 注 · 覆盖 20.4% · 每期期望净亏 ¥2.04`，一行字，把"理性娱乐"从口号变成事实。
3. **把首屏噪音换成"本期真信息"**（P0-3 后半 + P1-8）—— 连错文案改成"该档 30 期命中 6 期 / 随机基线 14.3%±12.5pp"，简表加一行总结。保留负反馈，去掉伪建议。
