# 特码智能选号助手（PWA 单页版）

轻量、浅色、单列的选号面板。首页自上而下只有 5 个模块：顶部开奖栏 → 近 30 期策略温度计 → 下期智能主推 → 近 100 期热度分布 → 近 30 期命中简表（完整历史在弹窗里）。

## 算法（三策略综合评分，不做任何杀号）

选号只看三组策略给出的号码与分数，没有杀码、冷却池、排除池等任何剔除环节：

- `#1 热态`、`#2 遗漏`、`#3 周期` 三组各 7 码，仍由原版加权评分 + `selectBalancedSeven` 做区间／波色／单双／大小／尾数均衡选出。
- `scoreAllNumbers()` 把 49 码全部纳入统一评分（`rankCandidatesFromPlan` 直接复用该排序）：
  - 百分位：把每张策略分数表换算成 0~1 的排名百分位（该表最高分 = 1）；
  - 基础分 = `0.40 × 热态百分位 + 0.34 × 遗漏百分位 + 0.26 × 周期百分位`（热态与遗漏更贴近特码短期走势，周期作节奏校正，故权重依次递减）；
  - 组内加成：进入该策略最终 7 码 +0.30（热态）／+0.24（遗漏）／+0.18（周期）；
  - 共识加成：同时进入两组及以上策略再 +0.12，让三策略共振号码优先。
- `[ 5码 ] [ 7码 ] [ 10码 ] [ 12码 ]` 四档取同一份综合分排序从高到低的前 N 码，档位之间严格是包含关系。
- 第五档**不是固定 18 码**，而是 `综合分前 12 码 ∪ (#1 热态 ∪ #2 遗漏 ∪ #3 周期 去重)`。加上综合分前 12 码是为了兑现「档位之间严格包含」——否则 12 码档里会有号码不在并集档里（历史实测约 15.6% 的期数会破坏包含关系）。码数随当期三组重叠程度浮动：全历史实测 **14~21 码，平均 18.2 码**。按钮文案为「并集全取 N码」，N 随当期变化；表头显示「当前并集（N码）」、复制预览显示「三组并集共 N 码」、锁定记录显示「三组并集 N 码」。
- 主推卡片下方「本档构成」显示当前档位里属于热态／遗漏／周期各几个号码、其中几个被两组以上选中，旁边有「这些词什么意思？」按钮打开术语说明弹窗。
- 主推卡片有一行**成本 / 覆盖 / 期望**：`N 注 · 覆盖 N/49（xx%） · 每期投入 ¥N · 期望净亏 ¥x.xx`（按 1 注 1 元、赔率 48 倍计，回报率恒为 97.96%，与选号方式无关）。
- 近 30 期策略温度计与参考信号（当前连错期数、近 20 期命中数）都按当前档位统计，是纯看板，不反向影响评分。

## 首页 5 个模块

1. 顶部栏：最新期号、上期开奖（红／蓝／绿波球，特码高亮）、`一键同步`、数据管理入口。
2. 近 30 期策略温度计：用进度条展示 `#1 / #2 / #3` 近 30 期命中数与命中率。「偏冷／正常／偏热」按二项分布动态判定（低于均值 −1σ 为偏冷、高于 +1σ 为偏热），底部基线说明随当前档位变化（写清该档覆盖率与 30 期 95% 正常区间），避免把随机起伏误读成趋势。
3. 下期智能主推：一行与随机基线的对照（命中数 / 基线 / 95% 区间 / z 值）、当前连错期数（附带「随机下约 x% 概率」）、5 档码数一键切换、波色球与简短标签、成本覆盖期望行、`一键复制推荐号码`（中文逗号，如 `05，21，37`，复制后按钮保持「已复制 N 码 ✓」）、`锁定本期`（切档后会提示已锁定的是哪一档）、术语说明入口。原来的 `选号依据` 模块已整体移除，页面不再出现杀码或排除口径，也不再输出「可优先参考 / 建议谨慎参考」这类把随机事件包装成建议的措辞。
4. 近 100 期热度分布：7×7 网格展示 49 个号码出现次数，按二项基线标记偏热/偏温/偏冷，并在图例下方写明统计口径（特码 100 次抽取、全奖 7 球 700 次抽取），不再有期号导航条。
5. 近 30 期命中简表：默认列出最近 30 期，上方有汇总行（命中 N/30 期 · 最长连错 N 期 · 累计 N 注 · 随机基线区间），未中显示为浅灰点而不是满屏减号；`查看全部` 打开弹窗查看完整历史（1786 期有效数据），弹窗内含年度命中率总表、年份切换、期号搜索、仅看命中、分页与展开全部。

## 保留的原有能力

- 一键同步最新开奖：读取仓库 `data/draws.json`（GitHub Pages 也尝试原始文件）；仓库无更新时尝试原上游及代理。只把连续、有效且不冲突的期号写入本机，发现缺口或冲突不会静默写入。同步状态分三态且视觉可分：进行中（蓝色 + 按钮转圈）、✅ 已同步 N 期、⚠️ 没有更新的期次（不是失败）、❌ 同步失败（附人话原因）。
- 内置离线底库（`index.html` 内 `COMPRESSED_DATA`，与 `data/draws.json` 一致，同步至 `2026-326`，共 1787 期，其中 1 期（2022-132，正码重复）不参与有效统计，可用 1786 期）。
- PWA / Service Worker 离线缓存、版本化静态资源；`src/constants.js`、`index.html`、`sw.js` 三处构建号由测试校验。
- 号码按红波、蓝波、绿波显示：开奖球、主推球、三组面板、热度格、历史开奖号、锁定记录与手动输入均带波色。
- 锁定本期快照（含当前码数与号码）并存在本机；开奖录入或同步后自动归档并显示命中结果，随导出备份一起保存／导入。
- 导入／导出备份、撤销、清空、连续期号校验与 5000 期上限。导出格式为 `schemaVersion 3`。
- 备份口径已写清：内置底库随页面更新、不需要导出；「导出本机记录」只保存你手动补录/同步到本机的期次与锁定快照，并在文件里附带 `builtInDatabase` 版本信息。
- 响应式：桌面居中最大宽度 880px；手机端按钮通栏、球体与 7×7 网格不溢出。

本地数据键为 `mark6_tool2_heat_v2`；旧版浏览器缓存不会被删除。首次使用及更新需要联网；Service Worker 提供离线缓存，同步需要网络。仓库数据仍由 GitHub Actions 定时更新。

## 开发

```sh
npm ci
npm test
npm start
npm run sync
```

构建版本需同步更新 `src/constants.js`、`index.html`、`sw.js` 与 `manifest.webmanifest`，当前为 `2026.11.23-r27`。

### 代码结构说明（改代码前请先看）

`index.html` 是唯一的应用页面：内联 `<style>` + 内联 `<script>`（选号引擎、渲染、交互全部在里面），另外只加载一个模块 `./src/note-sync.js`（同步）。

`src/` 下其余模块（`app.js`、`combined.js`、`dailyfive.js`、`six-tier*.js`、`replay-*.js`、`rhythm.js`、`tool1/`、`strategy.js`、`statistics.js`、`storage.js`、`copy.js`）是历史版本（工具 1 / 工具 2 / 六档）的引擎与旧页面逻辑，**当前页面不加载它们**，只被测试与脚本引用。`sw.js` 因此只预缓存页面实际用到的文件，避免首次安装多下载约 300KB 永远不会执行的代码。

注意 `src/strategy.js` 与 `index.html` 内联脚本各有一份 `selectBalancedSeven`（前者被测试使用，后者是页面真正跑的），改选号逻辑必须同时改两处及 `src/six-tier.js`。
